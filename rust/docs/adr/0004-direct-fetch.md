# ADR 0004: 평상시 조회는 직접 호출, 웹뷰는 대체 경로 (S3·S5 결과)

- 날짜: 2026-11-16
- 상태: 채택(macOS). Windows는 실제 기기 확인 대기
- 관련: 계획서 4-3 ①, 5-1, 7장(로그인 쿠키)

## S5: 번들 id를 `com.usagemeter.app`로 두면 Swift 버전 로그인이 이어지는가

`tauri build --config '{"identifier":"com.usagemeter.app"}'`로 만든 시험 번들에서 Claude·Codex 조회가 다시 로그인하지 않고 성공했다(3회 모두).
→ **Rust 정식판은 번들 id `com.usagemeter.app`를 유지한다.** WKWebView 기본 저장소(`~/Library/WebKit/com.usagemeter.app`)를 그대로 쓰므로 사용자는 다시 로그인할 필요가 없다. 개발 빌드는 `com.usagemeter.app.rs-dev`로 분리한다.

## S3: 웹뷰 없이 reqwest(rustls)로 직접 부르면 막히는가

웹뷰 경로와 직접 경로를 같은 시점에 둘 다 실행해 비교(`UM_S3=1`).

| AI | 시도 | 직접 경로 성공 | 웹뷰와 값 일치(5시간·주간) | 직접 경로 시간 |
|---|---|---|---|---|
| Codex | 8 | 8 | 8 | 0.7~1.8초 |
| Claude(로그인 상태) | 3 | 3 | 3 | 0.7~0.8초 |
| Claude(로그아웃 상태) | 20 | 같은 판정(403 not_logged_in) | - | 0.3~0.4초 |

Cloudflare 차단은 없었다. 계획서의 통과 기준(24시간 5분 간격 95%)은 아직 채우지 못했다. 짧은 표본이다.

## 채택한 방식

- 평상시: 직접 호출. 쿠키는 처음 한 번 로그인 웹뷰 저장소에서 읽어 **메모리 쿠키 통**에만 둔다(디스크·로그에 남기지 않음).
- 실패하면 쿠키를 다시 읽어 한 번 더, 그래도 실패하면 **임시 웹뷰 경로**(조회할 때만 만들고 파기)로 판정한다.
- Gemini는 agy가 1순위, 실패하면 임시 웹뷰(DOM 파싱).
- `UM_DIRECT=0`으로 직접 경로를 끌 수 있다.

## 메모리 (시험 번들, 20초 주기 5분, `measure-memory.sh`)

| 시점 | 본체 | WebKit 하위 | 합계 |
|---|---|---|---|
| 30초 | 25 MB | GPU 5.1, Networking 5.9 | 36.0 MB |
| 90초 | 27 MB | Networking 5.9 | 32.9 MB |
| 180~300초 | 30 MB | Networking 5.9 | **35.9 MB(변화 없음)** |

평상시 WebContent 프로세스 0개. Swift 버전(본체 약 102 MB + WebContent 약 31 MB)의 약 1/4.

## 남은 확인

- 24시간 연속 직접 호출 성공률(계획서 S3 기준).
- 서버가 세션 쿠키를 갱신(Set-Cookie)하면 메모리 쿠키 통에만 반영되고 웹뷰 저장소에는 반영되지 않는다. 재시작 후 옛 쿠키가 거절되면 웹뷰 경로가 저장소를 갱신하므로 동작에는 문제없지만, 필요하면 갱신된 쿠키를 저장소에 다시 써 넣는다.
- Windows(WebView2 쿠키 읽기는 메인 스레드 밖에서: Tauri 문서의 교착 주의).
